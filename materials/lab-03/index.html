Лабораторная работа № 3

Git и каталог книг

Добавьте карточку книги в общий проект через fork и pull request. Затем исправьте её по замечанию в том же pull request.

Открыть учебный репозиторий

Задача

Предложите изменение команде

Команда ведёт учебный каталог книг на GitHub. Вам нужно добавить отдельный Markdown-файл с карточкой книги, показать изменение на проверку и исправить его по замечанию. Программировать приложение не требуется.

Работа выполняется индивидуально. Ориентир по времени — 90 минут. Если замечание преподавателя придёт позже, завершите исправление после занятия.

Понадобятся Git, учётная запись GitHub и учебный репозиторий.

Перед началом

Посмотрите устройство проекта

Откройте репозиторий на GitHub. Найдите README.md, шаблон карточки, готовый пример, папку books/ и .gitignore. Посмотрите историю одного файла: кто и когда внёс изменение.

Получите у преподавателя номер или тему своей книги. Каждый участник создаёт свой файл: общий список редактировать не нужно.

Порядок работы

Пройдите путь от fork до pull request

  1. Получите копию. Зарегистрируйтесь на GitHub, если нужно. Сделайте fork учебного репозитория, склонируйте свой fork на компьютер и создайте отдельную ветку, например add-book-17.
  2. Добавьте карточку. Создайте в books/ Markdown-файл по образцу. Укажите название, автора или авторов, год и короткое описание. Можно выбрать реальную книгу или придумать учебный пример; описание напишите своими словами.
  3. Проверьте изменение. Посмотрите git status. Добавьте только нужный файл в индекс и посмотрите git diff --cached. Убедитесь, что в коммит попадёт именно ваша карточка, затем сделайте коммит с понятным сообщением.
  4. Проверьте .gitignore. Создайте учебный черновик в папке scratch/ и убедитесь, что он не появляется среди файлов для коммита. После проверки черновик можно удалить.
  5. Предложите изменение. Отправьте ветку в свой fork и откройте pull request из этой ветки в основной репозиторий. Назовите книгу в заголовке и кратко напишите, что добавили и что проверили.
  6. Исправьте замечание. Прочитайте комментарий преподавателя, измените карточку в той же ветке, сделайте второй коммит и отправьте ветку снова. Исправление появится в уже открытом pull request.

Fork — ваша копия проекта на GitHub; clone — копия на компьютере. Pull request позволяет показать разницу и обсудить её до включения в основной проект.

Подсказка

Команды для работы

Замените адрес, номер и имя файла на свои. Не копируйте угловые скобки из примера буквально.

git clone <адрес-вашего-fork>
git switch -c add-book-17
git status
git add books/<имя-файла>.md
git diff --cached
git commit -m "Добавить карточку книги № 17"
git push -u origin add-book-17

После исправления замечания:

git diff
git add books/<имя-файла>.md
git commit -m "Исправить карточку книги № 17"
git push

Если Git просит указать имя и электронную почту автора коммита, настройте их по инструкции преподавателя. Перед первым коммитом проверьте, какой адрес будет виден в истории публичного репозитория.

Результат

Ссылка на ваш pull request

Передайте преподавателю ссылку на pull request способом, который он укажет. В нём должны быть видны:

  1. Карточка книги в отдельном Markdown-файле.
  2. Первый коммит с добавлением карточки.
  3. Замечание преподавателя и второй коммит с исправлением в том же pull request.
  4. Отсутствие случайных файлов и локального черновика в изменениях.

Не закрывайте и не создавайте новый pull request ради исправления. Если замечание непонятно, уточните его в обсуждении. Скриншот или отдельный документ не заменяют ссылку: результат работы — сам репозиторий и история изменения.

Самопроверка

Что важно проверить

  • Pull request направлен из вашей ветки и fork в исходный репозиторий.
  • Карточка находится в нужной папке и оформлена по образцу.
  • Сообщения коммитов объясняют добавление и исправление.
  • В изменении нет случайных файлов, настоящих паролей, токенов и личных данных.

.gitignore помогает не добавлять локальные файлы, но не удаляет из истории то, что уже попало в коммит.
