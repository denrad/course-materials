Лабораторная работа № 7

REST API службы доставки

Выполните четыре задания в Swagger UI: найдите и отмените отправление, изучите историю, измените пункт выдачи и создайте новый заказ.

Работа индивидуальная. Устанавливать программы и писать код не требуется. Уделите особое внимание правильному JSON.

Открыть стенд и Swagger UIЧитать инструкцию

Цель работы

Научиться выполнять запросы к REST API через Swagger UI: находить нужную запись в списке, получать подробности и историю отслеживания, отменять и изменять отправления, создавать новое отправление. Особое внимание уделяется телам запросов в формате JSON: названиям полей, допустимым значениям и идентификаторам пунктов выдачи.

Перед началом

Работа выполняется индивидуально в браузере на учебном стенде. Программировать и устанавливать дополнительные инструменты не требуется.

  1. Откройте документацию API и панель заданий.
  2. В форме регистрации укажите фамилию, имя и группу, затем нажмите Получить токен.
  3. Скопируйте токен и нажмите Подключить. Токен даёт доступ к вашим учебным данным: не публикуйте его и не включайте в скриншоты.
  4. Выполните задания в одном сеансе. Срок действия учебного сеанса — 24 часа. Повторная регистрация создаёт новый сеанс с новыми отправлениями и отдельным прогрессом.

В верхней части страницы расположена панель прогресса, ниже — Swagger UI. После успешного API-запроса прогресс перечитывается автоматически. Сообщение о его обновлении и отметка задания показывают технический результат; это не оценка преподавателя.

Как отправлять запросы в Swagger UI

  1. Найдите в документации нужный endpoint и раскройте его.
  2. Нажмите Try it out, заполните параметры и, если endpoint принимает тело запроса, отредактируйте JSON в поле Request body.
  3. Нажмите Execute и проверьте код ответа и JSON-ответ сервера.

В JSON:

  • имена полей и текстовые значения заключаются в двойные кавычки;
  • между полями ставится запятая, после последнего поля запятой нет;
  • строковые значения, например "pickup_point" и "cheb-003", должны быть в кавычках;
  • не добавляйте в тело комментарии, пояснения или лишние поля.

В примерах ниже {shipment_id} — поясняющее обозначение. В запросе замените его на фактический shipment_id, полученный из ответа API; фигурные скобки в адрес запроса вводить не нужно.

Задание 1. Отмените отправление

Иванов Иван Иванович отказался от посылки, отправленной в пункт выдачи на ул. Гузовского, 16.

  1. Выполните GET /pickup-points. Найдите в ответе пункт выдачи с адресом ул. Гузовского, 16 и запомните его pickup_point_id.
  2. Выполните GET /shipments. Найдите отправление получателя Иванов Иван Иванович и убедитесь, что у него указан найденный пункт выдачи. Скопируйте shipment_id именно этой записи.
  3. Выполните POST /shipments/{shipment_id}/cancel, подставив ID отправления. Тело запроса не требуется.
  4. Проверьте ответ: статус отправления должен стать cancelled. После запроса в панели прогресса появится отметка о выполнении задания.

Задание 2. Посмотрите состояние и отслеживание

Узнайте, где находится отправление Петрова Петра Петровича и какой статус был последним.

  1. Выполните GET /shipments и найдите отправление Петров Пётр Петрович. Запишите его shipment_id.
  2. Выполните GET /shipments/{shipment_id}/tracking для этого отправления.
  3. В истории сравните значения occurred_at. Последняя по времени запись показывает последний статус. Сопоставьте её с текущим status отправления из списка или ответа GET /shipments/{shipment_id}.
  4. Прочитайте пункт выдачи или адрес доставки в данных отправления. Если указан pickup_point_id, сопоставьте его с адресом в ответе GET /pickup-points.

Задание будет отмечено после успешного просмотра списка отправлений (или данных целевого отправления) и истории отслеживания.

Задание 3. Измените пункт выдачи

Сидоров Сидор Сидорович просит перенаправить посылку в ПВЗ на ул. Ленинского комсомола, 23к3.

  1. Выполните GET /pickup-points и найдите ID пункта по адресу ул. Ленинского комсомола, 23к3.
  2. Выполните GET /shipments и найдите отправление Сидор Сидор Сидорович. Скопируйте его shipment_id.
  3. Откройте PATCH /shipments/{shipment_id}, нажмите Try it out и замените содержимое Request body на JSON ниже, подставив найденный ID ПВЗ:

json { "pickup_point_id": "cheb-003" }

В этом примере cheb-003 — ID ПВЗ на ул. Ленинского комсомола, 23к3. Если в ответе GET /pickup-points указан другой ID, используйте значение из ответа.

  1. Нажмите Execute. Убедитесь, что в ответе pickup_point_id изменился на нужный ID. Для этого частичного обновления достаточно передать pickup_point_id: не отправляйте старое значение и не добавляйте delivery_address.
  2. При необходимости выполните GET /shipments/{shipment_id} и проверьте сохранённый пункт выдачи. Задание засчитывается, когда у отправления указан нужный ПВЗ.

Проверьте JSON перед отправкой: кавычки должны быть двойными, имя поля — точно pickup_point_id, значение — строковый ID из справочника. Тело запроса должно быть JSON-объектом, как в примере, без текста вокруг него.

На примере ниже показаны тело запроса и ответ Swagger UI после успешного изменения пункта выдачи. В реальном запросе shipment_id будет вашим личным.

Задание 4. Создайте отправление в ПВЗ

Создайте отправление для нового получателя с доставкой в ПВЗ на ул. Водопроводная, 22.

  1. Выполните GET /pickup-points и найдите ID ПВЗ по адресу ул. Водопроводная, 22.
  2. Откройте POST /shipments, нажмите Try it out и укажите нового получателя и найденный ID. Например:

json { "recipient_name": "Алексеев Алексей Алексеевич", "delivery_method": "pickup_point", "pickup_point_id": "cheb-002" }

В примере cheb-002 соответствует ул. Водопроводная, 22. Сверьте ID со справочником ПВЗ перед отправкой. Имя получателя можно выбрать самостоятельно; используйте вымышленные данные.

  1. Нажмите Execute. Ожидаемый код ответа — 201. Сохраните выданный shipment_id и проверьте, что ответ содержит заданные recipient_name, delivery_method и pickup_point_id.
  2. Выполните GET /shipments и убедитесь, что новое отправление появилось в списке. После этого в панели прогресса будут отмечены все четыре задания и появится сообщение об успешном завершении лабораторной.

На примере ниже показано тело JSON для создания отправления и ответ сервера с кодом 201. При выполнении работы сверьте ID ПВЗ с ответом GET /pickup-points.

Скриншоты для отчёта

Приложите к отчёту пять скриншотов:

  1. Отмена отправления: запрос/результат, по которому видно получателя или ID, и ответ со статусом cancelled.
  2. Отслеживание отправления Петрова: история с последним событием и его временем; по возможности также покажите текущее состояние.
  3. Изменение доставки: тело JSON-запроса PATCH и ответ, где указан новый pickup_point_id.
  4. Создание отправления: тело JSON-запроса POST и ответ 201 с созданным отправлением.
  5. Итоговая панель прогресса со всеми четырьмя выполненными заданиями и сообщением «Задание успешно выполнено! На этом лабораторная работа завершена.»

Перед отправкой проверьте, что токен, заголовок Authorization и другие секреты не попали в кадр. При необходимости прокрутите Swagger UI, уменьшите масштаб страницы или обрежьте изображение, сохранив видимыми нужные запросы и ответы.

Критерии выполнения

  • все четыре задания отмечены как выполненные в панели прогресса;
  • отправление Иванова отменено;
  • студент посмотрел текущее состояние и историю отправления Петрова;
  • отправление Сидорова перенаправлено в ПВЗ на ул. Ленинского комсомола, 23к3;
  • новое отправление создано для ПВЗ на ул. Водопроводная, 22 и найдено в списке;
  • к отчёту приложены пять скриншотов без токена и иных секретов.
