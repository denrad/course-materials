# Материалы курса

Публичный сайт с готовыми презентациями, раздаточными материалами, кейсами и
полезными ссылками курса «Инструментальные средства разработки программного обеспечения».

Внутренние сценарии, черновики и преподавательские заметки в этот репозиторий
не переносятся.

## Как опубликовать материал

1. Подготовить финальную версию файла, безопасную для открытой публикации.
2. Положить её в `files/` в отдельную папку занятия, например
   `files/2026-01-programming-before-code/`.
3. Добавить на соответствующую карточку ссылку и дату публикации.
4. Просмотреть сайт локально и открыть pull request в `main`.

При добавлении новой карточки назначайте `order`, равный максимальному
`order` существующих материалов плюс один. Затем добавьте материал в
`MATERIAL_IDS` в `tests/test_site_build.py` в том же порядке; тест проверяет
каталог карточек и не даст незаметно вставить новую работу между существующими.
`ROUTE_IDS` использует этот список. Если сдвигается порядок отдельной страницы
перенаправления, обновите и её ожидаемый `order` в тесте и front matter.

Для Markdown-страницы перечислите каждую картинку и другой ресурс в allowlist
экспортёра. Проверьте, что итоговый путь ресурса совпадает с относительной
ссылкой в тексте, а файл присутствует в `_site/materials/<id>/` после сборки.

GitHub Pages собирает содержимое ветки `main` из корня репозитория штатным
способом после merge. Перед этим проверьте результат локально.

## Локальная сборка

Нужны Ruby 3.3.4, Bundler, Python 3.11+ и Make.

```sh
bundle install
make build
make serve
make test
```

`make build` создаёт сайт в `_site/`, `make serve` запускает локальный просмотр,
а `make test` собирает сайт во временный каталог и проверяет маршруты, карточки,
ресурсы и локальные ссылки. Эти же проверки выполняются в GitHub Actions; workflow
не публикует сайт.

Сливайте PR с новым материалом только после успешной проверки `Validate site`.
После слияния дождитесь завершения GitHub Pages deployment и откройте публичную
страницу вместе с добавленными изображениями.

Для буквального синтаксиса Liquid в новом Markdown-материале заключайте
пример в `{% raw %}` и `{% endraw %}`. GitHub Pages использует Jekyll 3.10,
где `render_with_liquid: false` из front matter не отключает обработку Liquid.
